# 副业体检诊断框架

这是实际诊断具体机会时的完整工作参考。目标不是预测必赚，而是少踩不值得的坑，同时不因过度分析错过值得低成本验证的机会。评估“它值不值得占用我的资源”，而不只是“别人能不能靠它赚钱”。

项目价值、人项匹配与当前时机共同决定结论；它们是定性变量，不构成评分或概率。

## 1. 证据强度

先问：这个赚钱机会成立的证据有多强？

| 强度 | 例子 | 对结论的含义 |
| --- | --- | --- |
| 弱 | 单个博主自述、收益截图、朋友月入、爆款账号/店铺、课程案例 | 只证明成功存在，不能推断普通人的成功概率。 |
| 中 | 多个独立执行者、多平台真实成交、长期存在的模式、持续需求、独立来源互证 | 值得进一步检查项目和人项。 |
| 强 | 自己收到询盘、有人愿付款、真实订单、可靠经营数据、小规模测试、多次相似实验 | 可更快转入执行或验证。 |

主动识别幸存者偏差、选择性展示、隐藏成本和营销叙事。“有人月入 3 万”不是项目成立的充分证据。

## 2. 项目体检

检查生意结构，而非只看售价：

- **赚钱结构**：谁付款、为何付款、客单价、是否复购。
- **完整成本**：原材料、平台抽成、广告、API/Token、软件、物流、包装，以及沟通、修改、售后、维护。售价不等于利润。
- **获客**：自然流量、广告、私域、地推、内容、销售或人脉从何而来；很多副业难在获客，不在交付。
- **交付与需求**：能否稳定兑现承诺；是真需求，还是由少数成功案例想象出来的需求。
- **竞争与依赖**：是否易复制、易价格战，是否依赖平台流量/算法、API、政策漏洞或某模型能力。

## 3. 执行者体检

只收集会改变判断的信息，不重复已知上下文。看：

- 当前能力：可独立交付、借助工具可交付、可快速学习，还是完全不具备；
- 资源：客户、流量、社群、账号、供应商、人脉、行业关系、设备、资金、作品集、数据、渠道；
- 可持续时间和精力：不严重挤压学习、工作、休息和既有项目下，每周真正愿稳定投入多少；
- 可承受损失：愿意试错的资金、时间、注意力，不等于账户余额；
- 当前最缺：现金流、技能、作品集、商业经验、客户、行业认知、人脉、方向或可选性；
- 工作方式偏好：销售、陌生拜访、沟通、反复修改、售后、露脸、私域、重复劳动、创造型工作，以及长期方向。

偏好用来估计长期执行摩擦，不能自动否决；也不要求每个副业都匹配十年人生规划。合法、划算的纯现金流同样有价值。

## 4. 能力缺口

“不会”不等于“不能”。

| 类型 | 判断 | 合理动作 |
| --- | --- | --- |
| 可学习缺口 | 可低成本边做边学，失败主要损失自己的时间 | 可以尝试。 |
| 前置能力门槛 | 有基本能力才可安全交付 | 先学习、Demo、自用或模拟项目。 |
| 不可接受缺口 | 能力不足会造成严重客户损失、法律/安全问题或重大责任 | 不让真实客户承担练习风险。 |

## 5. 时机判断

允许“好项目 + 合适的人 + 错误的时间”。检查注意力是否被已有项目、考试或求职占满；是否只差一步才可安全交付；是否暂缺真实场景但即将进入相关行业；市场窗口是否成熟；资金承受力是否足够。

若现在不合适，结论可为“值得观察”，并写出重新评估的可观察触发条件，而不是笼统等待。

## 6. 复合收益与失败收益

价值包含金钱、能力、可沉淀资产、行业认知、客户/人脉、未来机会和主观价值，减去综合成本；不要机械量化。资产可以是作品、代码、模板、工作流、客户、数据、内容账号、品牌、SOP、供应链、行业知识或产品组件。

运行**失败收益测试**：假设最终收入为 0，执行者还能带走什么？若钱和时间都没了且无沉淀，提高进入门槛；若可得技能、作品、客户认知、行业经验、代码或真实反馈，低成本试错价值提高。这不是鼓励失败，而是提高失败的价值密度。

## 7. 第 100 次、人工 API 与复利

对每个机会都运行**第 100 次测试**：做第 100 次时，自己相较第一次具体强在哪里？这个检查不依赖是否使用 AI。

只有当实际履约链条是**客户 → 执行者 → AI → 执行者检查/修订 → 客户**时，才检查**人工 API**：若重复后主要只是更会写 Prompt、转述需求和检查 AI 结果，就可能是人工 API。若履约根本不使用 AI，即使工作高度重复且复利弱，也只能称为**手工/低复利现金流**，不是人工 API。

人工 API 可以是合法、低风险且划算的现金流，尤其当用户缺现金且流程高度自动化；但不能自动称为高成长。无论是否使用 AI，更强复利都来自行业理解、需求分析、技术/自动化、客户、数据、模板、组件或标准方案。

再问“做一次后，下次是否更容易？”可形成：人工服务 → 模板 → SOP → 自动化 → 标准方案 → 产品。没有复利不等于不值得；短时、合法、低风险且现金收益显著的工作应诚实标为现金流项目。

## 8. AI 必要性

AI 项目从真实问题出发，问“真的需要 AI 吗？”按最简单有效的阶梯选择：

简单规则 → Excel/现成软件 → Python/传统自动化 → API → LLM → Agent。

不要因为拥有 AI 而寻找 AI 化的问题。若低复杂度工具已充分解决问题，AI 不是卖点；只有它带来明显、可验证的效率或价值时才增加复杂度。

## 9. Risk Breaker｜风险否决器

优先检查知识产权、商标、肖像/人格权、学术诚信、隐私、数据安全、技术责任、客户损失、平台规则、资金以及法律/监管风险。

风险不是“执行力不够”的问题。先找能保留核心商业价值、同时降险的安全相邻方案；例如将不合规 AI 代写改为真实数据整理、图表、公开资料检索、引用核验、格式调整或分析框架。若重大风险当前不可合理规避，直接给出“风险否决”，即使资金投入很低。

## 10. Analysis Breaker｜分析熔断器

分析有机会成本。若风险基本可控、损失可承受、有一定真实需求证据、失败有所得、MVP 很便宜，且继续搜集信息不会明显提高决定质量，就明确说：**分析到这里已经足够；最大的未知只能通过真实行动获得。**

转入单一关键未知的实验，不用额外 SWOT、PEST、波特五力、商业模式画布或几十项评分制造专业感与拖延。

## 11. MVP 与 Exit Trigger

MVP 是用最低成本验证**当前最大单一未知**，不是功能更少的完整产品。先问“我们最不知道什么？”：

| 最大未知 | 合适实验 |
| --- | --- |
| 是否有需求 | 测需求。 |
| 技术能否实现 | 做 Demo。 |
| 是否愿意付款 | 测真实付款。 |
| 真正痛点 | 找真实用户访谈。 |
| 获客是否可行 | 测一个真实渠道。 |

一个 MVP 必须恰好只有**一个主要停止假设 + 一个主要、可观察的通过/不通过门槛**。先选那个一旦不成立、整个项目就无需继续的假设，再把它写成能用一个明确事实判定的二元门槛。输出中的**成功信号**栏只写这一个门槛，不得用“and / 并且 / 同时”等措辞把多个必须达成的结果并列为成功条件。可以顺便记录技术有效性、交付设计、复用、获客效率、产品化及其他观察，但它们不得变成同一首个实验中的额外验证目标或另一个成功门槛。

第一个门槛未通过就停止或重设该假设；只有通过后，才按顺序设计后续的技术有效性、交付设计、复用、获客效率或产品化测试。不得用“多收集一些信息”将这些后续测试并入当前 MVP。对于尚无客户或一线经验的小商户自动化项目，首个门槛只验证是否有 **1 家真实商户** 愿意为有边界的礼宾式/人工辅助试点付款；技术优化和可复用产品测试都属于后续实验。

行动前设定 **Exit Trigger**：最大资金投入、最大时间投入、测试周期、核心目标、成功信号、失败信号、复盘节点和停止条件。标准必须在行动前确定，不能在失败后为沉没成本改写。

## 12. 解释失败实验

一次 MVP 失败仅说明实际被测假设没有得到支持，不等于整个行业或项目不行。检查实验设计、样本、渠道、实际测到什么和证据强度，再选择继续、修改实验、换方向或停止。

## 13. 用户价值排序

展示交易，例如“赚钱潜力较高，但与高频销售偏好冲突；额外收益是否值得交换长期执行摩擦？”用户自己决定价值排序。既不因偏好替其否决，也不以高收益要求其必须克服不喜欢的工作方式。

## 14. 最终原则

不存在同时高收益、低风险、低时间、高成长、高复利、有兴趣、低竞争、长期稳定、容易执行的完美机会。接受真实权衡：

- 值得、输得起、失败有所得，就试；
- 风险不可接受，不赌；
- 项目不错但人与时机不匹配，等待或换机会；
- 只是赚钱但确实划算，可以当现金流；
- 分析不再增值，进入真实世界。

## 15. 快速核对表

| 决策区域 | 改变结论的问题 |
| --- | --- |
| 证据 | 除个案、截图或营销叙事外，有多少独立的真实付费/重复实验？ |
| 项目 | 扣除获客、沟通、修改、售后与平台成本后，谁为何持续付费？ |
| 执行者 | 现有能力、资源、稳定时间和可承受损失能否安全完成？ |
| 能力缺口 | 是可学习、先学后交付，还是不能让真实客户承担的缺口？ |
| 时机 | 现在是否会挤压关键事项，何种条件出现后可重评？ |
| 复合收益 | 除现金外，能力、资产、行业认知、人脉和未来机会减去综合成本后，是否仍值得占用资源？ |
| 失败收益 | 收入归零后留下哪些能继续使用的资产或认知？ |
| 第 100 次 | 重复后是在积累能力/资产，还是低复利现金流？若 AI 中介实际履约，是否成为人工 API？ |
| AI | 不用 AI 或用更简单工具，能否同样解决真实问题？ |
| 风险 | 是否有不可合理规避的 IP、诚信、隐私、安全、责任或监管风险？ |
| Analysis Breaker | 风险、损失、需求证据、失败收益和低成本实验是否已足够，以至于继续分析不再改变决定？ |
| MVP | 哪个单一停止假设若不成立就应停止，哪一个可观察的二元门槛判定通过/不通过？ |
| Exit Trigger | 预先写定的投入、周期、信号、复盘和停止条件是什么？ |
| 失败实验解释 | 这次失败实际否定了哪个假设；实验设计、样本、渠道和所测内容是否足以改变继续、修改、转向或停止的结论？ |
| 价值排序 | 现金、成长、偏好摩擦和可选性的取舍由用户如何排序？ |

## 16. 常见误判

- 不要把每个机会都建议 MVP；重大风险或成本明显过高时应否决。
- 不要把每个风险都当放弃理由；风险可控时找相邻方案或做有边界实验。
- 不要把长期复利或人生规划当一切；纯现金流可以合理。
- 不要把用户偏好当绝对否决，或把能力缺口自动等同于不适合。
- 不要因单个成功案例就认定市场成立。
- 不要因一次 MVP 失败否定整个方向。
- 不要用数十指标、伪精确分数或无限分析制造幻觉。
- 不要替用户决定价值排序，或用“执行力”逼其承担不值得的风险。
- 不要遗漏**第 100 次测试**：每个诊断都要说明重复后的能力/资产变化。若 AI 中介实际履约，明确人工 API 风险；若非 AI 重复劳动复利弱，明确其为手工/低复利现金流，并设定相应边界。
- 不要让一个 MVP 同时肩负多个验证目标：一个实验只有一个主要停止假设和一个通过/不通过门槛，后续技术、复用、获客或产品化测试只能在它通过后顺序展开。
